# Demo 共享简报（5 个设计方向统一遵守）

## 1. 产品与用户

**ZCode 福利自动领取助手**——单机、单账号的本地自动化工具。到点自动：打开 ZCode 客户端 → 截图 → DeepSeek 视觉模型定位「领取」按钮 → 模拟点击 → 视觉校验结果弹窗；失败则关客户端重开重试，最多 5 次。

用户就是机主本人（技术型，Windows）。他打开面板只想知道三件事：
1. **现在什么状态**（在跑 / 待命 / 出事了）
2. **下一场什么时候**，还剩多久
3. **刚才那次到底成没成**，失败能不能回放看到当时画面

面板还兼任配置器：场次表、识别参数、词表、ZCode 路径、通知、清理。

**这不是营销页，是操作台。** 设计的第一职责是让状态一眼可读、让回放可信、让配置不出错。

## 2. 硬约束

| 项 | 要求 |
|---|---|
| 离线 | 纯静态 HTML/CSS/JS，**禁止 CDN、禁止外链字体/图片**，`file://` 双击可开 |
| 库 | 只用本项目已 vendor 的 GSAP：`../assets/js/vendor/gsap.min.js`（相对本文件所在目录）。也可纯 CSS/WAAPI，自行取舍 |
| 字体 | 只能用 Windows 自带字体栈。禁止假设有 Inter / Google Fonts |
| 语言 | 界面中文。中文文案必须自然、能落地，不许编造术语 |
| 图标 | 内联 SVG（1.75 描边、currentColor、20/16 两档），**禁止 emoji 当图标** |
| 无障碍 | 正文对比度 ≥ 4.5:1；键盘焦点环可见；`prefers-reduced-motion: reduce` 与 `?motion=0` 时必须静态呈现且不留透明残骸 |
| 视口 | 桌面优先（1440×900 设计基准），≤1120px 侧栏收成 72px 图标栏，≤720px 可用（不强求移动端完美） |

## 3. 内容模型（5 个 demo 必须完全一致）

### 3.1 侧栏导航（6 项，顺序固定）
`概览` / `流程` / `场次表` / `识别` / `运行日志` / `设置`
底部：连接状态（`本地服务已连接` / 黄灯 `连接断开`）、`v1.1 · 127.0.0.1:8760`

### 3.2 顶栏（所有页面常驻，四要素）
- 状态灯 + 双行：`空闲 / 自动领取待命`、`等待中 / 距下一场 6 分钟`、`执行中 / 第 2 次尝试 · 点击`、`成功 / 领取成功 · 10:00:03`、`失败·需人工 / 登录页,需要手动处理`
- 下一场：`16:00` + 倒计时 `02:13:09`（**必须真实跳动，秒级**）
- 总开关（ON 状态）
- 主按钮 `试领一次`

### 3.3 ① 概览
4 张统计卡：
- `下场时间` → `今天 16:00`，副 `距现在 02:13:09`
- `今日场次` → `3`，副 `启用 3 个 · 明日 3 场`
- `今日结果` → `✓ 2  ✗ 1`，副 `最近一次:成功 · 10:00:03`
- `运行状态` → `空闲`，副 `总开关:已开启 · 无任务在跑`

手动测试区：`试领一次(完整流程)` 主按钮、`演练一次(不点击、不关客户端)` 次按钮，下面一句说明（完整流程会打开/置顶客户端、截图识别、点击、校验,失败会关闭客户端重试最多 5 次;演练只截图识别不点击）。

上手检查（3 项，2/3 完成）：
- ☑ `填写 DeepSeek API Key` — `识别页 → 模型连接,填完点「连接与额度测试」` → 按钮 `去填写`
- ☑ `添加每日场次` — `场次表 → 添加场次,例如 10:00 / 16:00` → 按钮 `去添加`
- ☐ `打开总开关` — `顶栏右侧开关,开启后到点自动执行` → 按钮 `去开启`

本次执行（点「试领一次」后才出现，动效重点）：5 步 = `打开客户端` → `窗口就绪` → `截图定位` → `点击领取` → `校验结果`；带 `第 2 次尝试` 徽标；右侧是实时截图框（占位图 + 红色定位框 + 坐标标注）。

最近记录（3 行表格）：
| 时间 | 场次 | 结果 | 说明 | 尝试 |
|---|---|---|---|---|
| 今天 10:00 | 第 1 场 | 成功 | 第 2 次重试后领取成功 | 2 |
| 昨天 16:00 | 第 2 场 | 失败 | 5 次重试均未成功 | 5 |
| 昨天 10:00 | 第 1 场 | 成功 | 首次点击即成功 | 1 |
每行尾部 `查看`。

### 3.4 ② 流程
7 节点主流程：`触发` → `打开客户端` → `截图` → `视觉定位` → `点击领取` → `校验` → `收尾`
3 条出口分支：`成功弹窗 · 领取成功 + 开始体验`、`失败弹窗 · 领取失败 + 知道了`、`需人工 · 登录页 / 验证码 / 锁屏`
下方 4 张阶段卡（截图 / 定位 模型调用① / 点击 / 校验 模型调用②），每张写输入输出。
再下方判定规则表（8 行，列：阶段 / 判据 / 动作），与坐标换算块（窗口矩形 + 归一化中心点 = 屏幕坐标）。

### 3.5 ③ 场次表
表：`10:00 ☑ 尝试 5 重试 5s 最近 今天✓`、`16:00 ☑ …今天✓`、`22:00 ☐ …—`，右上 `添加场次`。
`未来 7 天预览`：今天 ●10:00 ✓ / ●16:00 / 22:00 未启用，之后 09-11 … 逐日列出。

### 3.6 ④ 识别
模型连接：Provider `deepseek(默认)`、base_url `https://api.deepseek.com`、API Key `••••••••••••7f3a`（可显示）、Model `deepseek-v4-flash-vision-exp`、temperature `0.2` 滑杆、detail `auto`，按钮 `连接与额度测试`
识别参数：`定位置信度阈值 0.70` 滑杆、`视觉超时 20s`、`点击后等待校验 2.5s`

### 3.8 ⑥ 设置
程序与 ZCode：`ZCode 程序路径 C:\Program Files\ZCode\ZCode.exe` + `自动探测`、`窗口标题匹配 ZCode`、`执行前全屏显示 ☑`、`启动后等待加载 5.0s`、窗口位置 `40 / 40 / 1240 / 860`
重试与节奏：`最多尝试次数 5`、`失败后重试间隔 5s`、`等待客户端启动 60s`、`截图前置顶等待 0.6s`、`界面渲染等待上限 20s`、`单场看门狗超时 240s`、`动手前需空闲 2.0s`
通知：`Windows 桌面通知 ☑`、`Webhook(可选)` 输入框
数据：`截图/日志保留 7 天` + `打开目录`
危险区：`清除全部截图` `清空日志` `重置配置为默认` `退出程序`（四个按钮，均二次确认）

## 4. 五个 demo 共同必须实现

### 4.1 三个状态必须能看
- **空闲**：默认
- **执行中**：点 `试领一次` 触发一段**剧本化的模拟执行**（约 14 秒）：顶栏状态切 `执行中`、概览出现「本次执行」面板、5 步依次点亮（含一次失败重试 → 第 2 次尝试成功）、实时截图占位交叉淡入、倒计时暂停、实时日志逐条追加、结束后状态转 `成功` 并在 4 秒后回 `空闲`；结束时在场次列表插入一条新记录
- **失败·需人工**：顶部横幅（红）+ 状态灯保持，可点掉

用一个统一的「DEMO 控制条」（右下角悬浮，明确标注 demo 专用）提供：`空闲` / `执行中` / `成功` / `需人工` 四个状态按钮 + `重播开场`。控制条本身也要符合该方向的设计语言，但视觉上要从产品界面里"轻"出来（虚线边框或半透明）。

### 4.2 页面切换
6 个页签全部要有真实内容（不允许空白页或"本页略"）。切页要有转场动效，且**不引起布局跳动**。

### 4.3 动效门槛（每个方向自己的语言，但底线一致）
- 开场序列：品牌 → 导航 → 顶栏 → 卡片，依次浮入（总时长 ≤ 1.4s）
- 导航选中指示器：滑动/绘制，不能是生硬换底色
- 倒计时：真实秒级跳动，数字 tabular-nums 不抖
- 状态灯：执行中呼吸、成功闪烁两次、失败持续脉冲
- 数字变化：滚动或翻牌，不许瞬变
- 切片：只用 transform / opacity（GSAP 侧优先 `x/y/scale/autoAlpha`），不动 width/height/top/left
- 退场比入场快；`prefers-reduced-motion` 与 `?motion=0` 全静态化

### 4.4 质量红线
- 语义色全站唯一：绿=成功、红=失败/危险、黄=重试/等待、蓝=进行中。品牌色只用于操作与选中，不参与状态表达
- 圆角体系定一次，全站一致（并在注释里写清规则）
- 按钮/输入框/占位文字全部过对比度检查；空状态、错误态、加载态都要有设计（不许大白板）
- 表格数字一律 `font-variant-numeric: tabular-nums`
- 不许出现 `—` 长破折号当装饰；不许编造精确数字（数据就用上面给的）
- 中文标点统一：逗号用 `,` 或 `，` 全文一致即可
