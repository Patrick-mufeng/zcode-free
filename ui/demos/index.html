ZCode 福利助手 · 前端重做方案选型

5 个设计方向，内容、功能与交互逻辑完全一致，只有视觉语言不同。每个都是可点的真实原型：六个页签都能切、「试领一次」会跑完一整段模拟执行（含一次失败重试）、顶栏倒计时真的在跳。

建议这样看：先点开两三个方向的「试领一次」看执行时的动效表现，再切到「运行日志」和「场次表」看数据密集页的排版是否还站得住。右下角的演示控制条可以随时切换状态（空闲 / 执行中 / 成功 / 需人工）。

五个方向

横向对比

方向视觉语言最适合的场景代价
A 极光仪控深色玻璃 + 极光光斑 + 轨道环倒计时 想要「一台仪器」的仪式感，长时间盯着看不累，深夜环境最耐看 玻璃与模糊层最多，低配机上开销略高；深色不适合白天强光下看
B 制图台深蓝图纸 + 坐标网格 + 尺寸标注 + 等宽字体 想强调「点得准、可复查」，把坐标与置信度当成一等公民展示 字号整体偏小、信息密度高，年龄偏大的用户会吃力；最「硬核」
C 纸面手册冷白纸面 + 零圆角 + 双线章节 + 印章 白天使用为主，想把它当一本说明书来读；浅色下表格最易读 与「自动化」的科技感距离最远；印章动效偏装饰，需要接受
D 硬边运维纯白机身 + 2px 黑框 + 硬投影 + 机械摇杆 最怕「以为它在跑其实挂了」，要在三米外一眼看清状态 视觉最吵，长期看容易疲劳；占据空间大，一屏信息量最少
E 静默方格石墨灰三级底色 + 1px 细线 + 唯一琥珀色 + 24 小时轨道 已经用顺手了，想让它常驻桌面、安静不打扰；信息密度最高 装饰最少，第一眼不够「惊艳」；需要一点时间才能看出讲究

共同做对的事

  • 状态一眼可读：五个方向都用同一套语义色（绿=成功、红=失败、黄=等待、蓝或琥珀=进行中），品牌色只用于操作与选中，不参与状态表达。
  • 执行全程可见：点「试领一次」后，顶栏状态、五步时间线、实时截图、实时日志四处在同一秒同步变化，含一次失败重试的完整过程。
  • 离线可用：纯静态 HTML/CSS/JS，不引 CDN、不引外链字体，双击就能开；动效只用项目里已经放好的那份 GSAP。
  • 可访问性达标：正文与次级文字对比度全部 ≥ 4.5:1（已用脚本逐元素实测），焦点环可见，系统「减少动态效果」或地址栏加 ?motion=0 时全部静态化且不留透明残骸。
  • 三档视口可用：1440 设计基准，1100 侧栏收窄，760 单列；三个宽度下都没有横向滚动条。

选定之后

  • 把这一个方向的 CSS 拆成 ui/assets/css/app.css，页面骨架合回 ui/index.html，然后按现有 api.js / events.js 的真实接口替换掉演示数据（进度见下方文件清单）。
  • 演示里已经在用的类名（.logline[data-level]、.chip[data-kind]、.shot[data-kind]、.step[data-state]）就是给正式版准备的接口，接真实数据时不用重新设计。
  • 没选中的四个方向不必删，可以留着作为后续换肤或「紧凑模式」的备选。
